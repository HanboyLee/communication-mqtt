## 二、 待办需求池 (Pending Backlog)

- [ ] **TODO-001**: MQTT Payload 发送预设模板
  - **优先级**：P1
  - **分类**：交互体验
  - **需求描述**：在发送区域支持选择预设的常用 Payload 模板（例如标准传感器 JSON、开关控制指令、时间戳上报等），点击后直接填充至输入框，支持用户自定义并保存常用模板。
  - **验收标准**：
    - 提供常用 JSON 模板下拉/弹窗列表。
    - 点击模板自动填入输入区，可二次编辑。
    - 自定义模板支持持久化保存至 `chrome.storage`。

- [ ] **TODO-002**: 消息日志多维度搜索与内容过滤
  - **优先级**：P1
  - **分类**：会话调试
  - **需求描述**：当消息流速较快或数量较多时，用户需要在当前会话 Tab 或所有日志中按关键字、消息方向（Rx/Tx）、时间区间进行搜索和即时过滤，并对命中词进行高亮。
  - **验收标准**：
    - 会话工具栏提供搜索输入框。
    - 输入关键字后，日志列表即时过滤或高亮匹配项。
    - 支持按方向（仅收/仅发/系统消息）切换显示。

- [ ] **TODO-003**: 会话消息导出支持（JSON / CSV / TXT）
  - **优先级**：P2
  - **分类**：数据工具
  - **需求描述**：当前会话工具栏具备导出按钮占位或简单输出，需要支持将当前选中的 Topic 会话或全部历史消息导出为本地文件（标准 JSON、CSV 或带时间戳的纯文本）。
  - **验收标准**：
    - 点击导出弹出格式选择（JSON / CSV / TXT）。
    - 触发 Chrome 下载保存到本地，内容包含时间戳、Topic、QoS、Payload。

- [ ] **TODO-004**: 连接异常诊断与友好重试交互
  - **优先级**：P2
  - **分类**：稳定性
  - **需求描述**：当 WebSocket / MQTT 连接发生错误或异常断开时，区分网络不通、认证鉴权失败（401/403）、超时等常见原因，并在界面提供明确的排错建议和手动一键重试倒计时。
  - **验收标准**：
    - 系统日志清晰输出错误原因分类。
    - 连接状态栏提供快捷重试按钮与倒计时。

- [ ] **TODO-005**: 消息流量与吞吐简报（Stats）
  - **优先级**：P3
  - **分类**：监控辅助
  - **需求描述**：在连接状态区域或会话栏显示轻量级统计指标（如当前已收包数、已发包数、收发总字节量、连接持续时长）。
  - **验收标准**：
    - 在界面可折叠查看当前连接的统计数据。
    - 断开连接或切换会话时可重置或按需累计。
